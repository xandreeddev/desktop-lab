# Lucent desktop

Consult docs/current-readiness.md and the ledger current_rollup for accepted-main evidence scopes before repeating historical pending claims.

Work from the repository root and inspect the existing state before edits. Read [user configuration](../../../site/src/pages/docs/desktop.astro) and [ownership](../../../site/src/pages/docs/system.astro) for the boundary relevant to the requested feature.

- `Desktop` gets implementations through `DesktopAdapters`; contracts retain Port names. Concrete production selection belongs in `platform.rs`.
- Tray descriptions/overflow and closed-dock names use the SDK's passive tooltip API with generated component tokens. The small transparent hint band is native buffer room only: keep the bar reservation exactly 48 logical pixels, the dock's display-grid origin, original hide travel, Content pointer policy and opening FrameSubmitted handoff. Never solve label clipping with a permanent fullscreen surface or wider input region. Tray menu behavior remains the existing client; the generic initial popover contract is one scope, without nested menus. See `docs/anchored-overlays.md` and `reports/measurements/lucent-anchored-overlays.json` for passed offscreen and single-output production pointer/static-capture scope. Native generic popover/keyboard/clipboard, bar click-through, exact fade timing/smoothness and current RSS remain separate acceptance; preserve those limits.
- `launcher::Launcher` owns private query/mode/selection/scroll and panel motion. Its view borrows snapshots and decoded Artwork; typed Intent values return shared operations to Desktop. Route child messages with Element::map and Effects::delegate. Do not import Desktop or its adapter bundle into the child, duplicate settings there, or add client-specific concepts to the framework. `widgets::Host` likewise owns private drag/calendar/timer state. Its view borrows snapshots and Artwork; updates borrow the root settings aggregate and return Save/Action/Error intents. One widgets/catalog.rs definition supplies selector metadata, token geometry, IPC validation and the compiled view. Do not restore parallel widget lists or pass the root/adapter bundle to widget views.
- Preference saves go through `persistence::Persistence`, the sole producer for the settings queue. Preserve one active revision plus latest pending snapshot, feature-owned failure state and explicit retry. Widget views receive save status and return retry intent; they never call SettingsPort. Do not route settings results back through generic Completed. Acknowledgement is adapter completion, not an automatic shutdown flush or power-loss guarantee.
- Widget drag previews remain private transient host state. Only a successful release snaps and commits through the pure move use case. Other preference saves must see the last committed placement. Hide/reset/invalid input cancel the rest of a gesture; start from the visible clamped origin after output changes.
- Widget buffers use client-owned bounds including the renderer's finite shadow support. Merge overlapping bounding rectangles until groups are disjoint, retaining catalog/visibility paint order; Wayland does not promise ordering within a layer. Freeze source geometry throughout drag capture. Keep input-only sources under a temporary pointer-pass-through preview, and route group redraws through generic SurfaceSpec contracts. Cancel on output resize/load; do not leak placements or widget identities into the renderer/domain.
- WidgetLayout is the canonical pure layout value. DesktopSettings flattens the default to legacy JSON keys and owns validated MonitorId profiles. Monitors owns connected client hosts/geometry/generations; views and updates borrow the selected layout and shared notes, never copied Desktop aggregates. Keep registry/clock observation out of profile persistence, exact instance redraw/clipboard identities, generation-bound routing and reflow cancellation. Shared panels use the selected output. Readiness requires every host's declared groups via explicit role/instance, so deploy the helper and supervisor together. See docs/monitor-layouts.md; simultaneous-output placement/input/clipboard, hotplug/suspend and secure-output acceptance remain open. One-output live-video resize and integer/fractional retargeting pass in reports/measurements/lucent-live-display-fit.json; do not broaden that result to every output/layout policy.
- CompositorPort observations and native Wayland hosts join by exact MonitorId in the client. Fresh focus/recovery can select an available host or wait in pending_focus; explicit input/selection retires pending authority, while resize and unchanged metadata do not. Keep compositor availability/error separate from generic command errors and preserve last-good data. Each named bar consumes its own observed WorkspaceRef; numbered shortcut policy stays client-owned. The adapter subscribes before queries, preserves bounded event fragments and uses absolute bounded command/snapshot IO. See docs/compositor-focus.md and the independent compositor-service consumer; do not equate read-only query compatibility with native multi-output acceptance.
- Geometry and animation targets share `shell_layout.rs`. Layout preferences belong in persisted domain settings, while screen limits and token-based geometry belong to the client. Preserve backward defaults, selection reachability and unrelated preferences.
- Edit `design/tokens.json`, then run `python3 scripts/generate-design-tokens.py`. Never hand-edit generated Rust/CSS or window rules. Native view styles use semantic/component tokens. Check rounded insets and keyboard focus as well as pointer hover.
- NativeAssets prepares the bundled theme-tinted artwork through `images::svg_mask`/Alpha8. Preserve icon dimensions and coverage; colored XDG fallbacks and wallpapers remain RGBA. CPU prepared bytes, texture payload and process RSS have different scopes; verify pixel equivalence and actual residency before claiming a memory improvement.
- Lucent owns shell UI and theme authority. `scripts/lucent-session.py` supervises the native desktop; polkit uses libpolkit-agent with native presentation, idle uses headless swayidle, and clipboard capture is separate. Keep secure lock recovery working. Never restart stock shell UI as a crash fallback; stock restoration is an explicit rollback.
- SessionScreen owns active-field routing, shared by its view and keyboard handling. Only login with no active attempt may edit/clear identity; prompted responses use zeroizing Secret storage. Keep connecting/verifying input disabled and authorization cancellation distinct from unlocking. Rebuild consumers together when aligning session-client releases; retain ext-session-lock, greetd and libpolkit-agent authority, disabled secure-client inspector/command sockets and atomic rollback copies. Credentials remain outside scenes, logs, process arguments and environment.
- Native supervision and activation share scripts/lucent_readiness.py. Require first submissions from every declared widget group rather than a fixed widgets buffer; no visible widgets means no widget surface. Preserve legacy fullscreen-client readiness for baseline/rollback, and deploy the supervisor/module together. Verify the service survives beyond the startup deadline; repeated explicit test restarts alone can hide a readiness failure.
- `ThemePort` receives a validated `ThemePalette`; `LucentTheme` exports generated tokens outward to apps. Omarchy’s headless templates may consume our colors, but stock themes must never overwrite the Lucent palette. Do not introduce a reverse theme hook. Keep backups and wallpaper preservation intact. Named palettes come from generated semantic tokens; extracted palettes use the design recipe. Keep network search/download behind `WallpaperCatalogPort`, pixel sampling behind `PaletteGenerationPort`, and request generations out of the generic renderer.
- Static wallpaper previews belong to previews::Previews, not the icon map. Keep one active decode and bounded latest demand; views receive the read-only prepared view. Current/target carousel demand and painting share visible_wallpapers. Preserve committed previews over older speculative results, explicit retry and dimension/entry/reuse limits. Prepared-byte counters deduplicate allocation identity; they exclude in-flight work, scenes and driver memory and must not be labeled RSS.

- Live browsing uses live_wallpaper::preview::Preview and the shared client wallpaper_carousel, not durable prepare or the static-image decoder. Keep source selection separate from Apply, at most one serial preview decoder body, two neighboring stills and five cache entries. Retain cancellation ownership until the terminal message confirms the old body returned; reject stale generations and clear transient demand/cache on close. Derive checked contain bounds from the actual hero geometry and density (max1024 physical pixels, no upscaling); alpha fitting must premultiply before resampling. No preview import/poster/preference writes or OS calls in views. Durable prepare can reuse exact valid immutable imports through bounded1024-entry descriptor/streamed-byte lookup; a miss still permits fresh imports and never deletes history. This is opportunistic reuse, not concurrent/global deduplication or an RSS guarantee. Owned one-output 1× synthetic-GIF native checks pass animated crops, select-only browsing, Tab/wheel, same-path Retry/Refresh, close/reopen and exact caller restoration (reports/measurements/lucent-live-wallpaper-previews.json). Multi-output/fractional/codec hardware, preview-specific resource cost and actual presentation smoothness remain separate; see docs/live-wallpapers.md.
- Wallpaper selection belongs in the child coordinator. Reserve intent before downloads; stage an immutable source snapshot, decode it through AssetPort, then commit. Supersede preparation but finish accepted commits before the latest pending choice. Carry the prepared image to completion; never change the selection before a fallible decode. Preserve explicit palette intent, source provenance and original files. Theme/login exports are eventual, not one atomic transaction.
- Background geometry uses the presentation-only `BackgroundTarget`, outside the pure domain. `Selection` retains one active refit and the latest desired physical size on the ordered appearance queue; the injected AssetPort adapter prepares it. Keep last-good pixels on failure, reject stale source/size completions and use explicit `wallpaper retry`. Refits never commit selection, generate colors or save preferences. Inspect `wallpaper_presentation`; one background surface does not establish per-monitor or fractional-scale support.
- The background owns the full display viewport. A settled dock uses a short bottom-anchored buffer; `shell_layout` translates display-grid geometry into surface-local coordinates including the shadow support. The launcher waits for a full `FrameSubmitted` before opening its morph, retains the large buffer until the settled closing submission and rejects stale close identities. Native hit coordinates are surface-local; VM input harnesses query compositor placement separately.
- Keybinding/root/submenu rendering uses the native picker, but discovery and actions remain Omarchy-owned. Preserve user extensions and exact selected values. Lock/login are separate secure clients; ordinary overlays cannot replace session-lock authentication.

For validation, use `cargo test --manifest-path lucent/Cargo.toml -p lucent-desktop` and the related domain/adapter tests. Run the ignored `visual_regressions` test explicitly on a Vulkan-capable system. It writes `reports/local/visual-tests/index.html`; review actual/diff images at 1×/2× and narrow sizes. Update goldens with `LUCENT_UPDATE_GOLDENS=1` only after reviewing intentional changes, then rerun without that flag. Keep unrelated golden changes out of the commit.

For a requested VM test/deployment:

1. `python3 vm/lab.py status`; use the existing Lucent guest and keep other profiles untouched. Check host memory before boot/build. The guest can be killed by host OOM independently of Lucent correctness.
2. `python3 vm/lab.py start lucent`; `python3 vm/run.py --sync lucent` transfers sources only. Use `vm/run.py --session lucent` for commands needing graphical-session variables. SSH credentials remain in ignored `.local-vms`; never publish them or feed them to an ordinary terminal.
3. Build the requested binaries, preserve a rollback copy, install through a temporary file and atomic rename, then restart only `lucent.service`. A shell UI change does not require reinstalling login or changing disks. Check service readiness, `lucent-cli inspect`, keyboard/click interaction and settings after restart.
4. Wallpaper tests must checkpoint the selected owned snapshot with `vm/wallpaper_checkpoint.py` before temporary selections. Cache pruning can remove it while another wallpaper is active. Restore the snapshot before normal IPC rollback; discard the private checkpoint only after the original desktop is verified. Keep settings backups in unique private temporary storage.
5. Use existing `vm/test-*.py` helpers where applicable; inspect their effects before running a broad suite. Capture sanitized local evidence and distinguish VM-only verification from hardware tests.

Use `python3 vm/measure-framework.py --seconds 120 --profile` for bounded CPU-stage samples. Its private systemd runtime override and stay-awake marker are restored on failure. Check actual profile activation and restoration; compare instrumented results with normal-mode measurements. Review source/binary identity and remove personal data before publishing reports.

For docs, keep library explanations under the library guides and runtime preferences under the desktop guide. `cd site && npm run dev -- --host 0.0.0.0` serves on LAN when requested; verify the actual listening port and HTTP response. Do not terminate unrelated servers. Source/built links must respect `withBase` for GitHub Pages.
