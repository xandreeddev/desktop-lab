# Lucent framework

Consult docs/current-readiness.md and the ledger current_rollup for accepted-main evidence scopes before repeating historical pending claims.

Read repository paths relative to its root. Start with the concrete client and follow its calls into the engine; the original project prompt contains proposed crates and features that do not exist.

- Public component/runtime contracts: `lucent/crates/lucent-api/src/lib.rs`.
- Surface-local overlays use `AnchoredSpec`, `Tooltip` and one explicit `Popover` focus scope. Keep anchor IDs as presentation identities and client actions/lifetimes outside the engine. Tooltips contribute paint only, use one cancellable calloop dwell deadline and never broaden native input coverage. Validate finite timing/placement before scheduling; preserve scoped keyboard routing, outside-press capture and still-live opener restoration. Nested menus/native popup roles are not implemented. Consult `docs/anchored-overlays.md` and its independent consumer; native/visual acceptance is separate from written fixtures.
- Engine: `lucent-ui` (layout/input), `lucent-wayland` (event loop/surfaces/workers), `lucent-render` (Vulkan resources/presentation).
- Domain contracts are **ports**; concrete or supplied implementations are **adapters**. The desktop composition root is `platform::desktop_adapters()` and its injected bundle is `DesktopAdapters`.
- Domain values and use cases cannot perform OS operations or expose renderer/transport types. Value objects should enforce a demonstrated invariant; public field structs and newtypes are not automatically validated. Keep screen/grid policy and design tokens in the client.
- Compositor adapters report actual state, including special workspaces. WorkspaceRef is a validated positive number, regular name or special name; Workspace.id and optional Window.workspace share it. WorkspaceCommand separates Select from ToggleSpecial; native selector prefixes and Lua literal escaping belong to the adapter. Modern addresses outrank display labels; legacy negative IDs normalize by name, invalid/ambiguous records have no action authority. Shortcut slots and their ordering belong to the desktop workspace presentation policy. Shadows carry color/offset/blur through `Shadow` and `Paint::Shadow`; the design system supplies elevation tokens, while the renderer implements only the generic falloff.
- Construct application identities with `AppId::new`; persisted IDs use the same validation. Use `Application::matches_window_class` for dock state and activation rather than duplicating identity rules or matching empty hints. Valid settings keep their string ID representation; invalid settings must remain preserved on disk.
- Construct Date with a validated year/month/day; weekdays are derived. Use its checked month_start for calendar arithmetic. Construct Placement through new; deserialization enforces the same finite-coordinate rule while retaining the x/y JSON shape. Negative positions are valid values. Grid spacing, navigation limits and output bounds are client policy; use cases validate bounds before mutation.
- Production selection belongs in composition roots. Tests inject adapters. `AssetPort` is a presentation contract because it returns decoded pixels; do not move it into the pure domain.
- NetworkPort consumes commands with non-Clone/non-Debug WifiCredentials. NetworkManager owns one cancellable system-bus connection, current transient identities, bounded command/event admission and signal-driven refreshes. Keep raw SSID octets, D-Bus paths and credential serialization distinct; a command acknowledgement is not scan/association completion. Pump signals while awaiting native replies, retire dependent handles on device removal and the connection on transport timeouts, and never echo D-Bus error bodies. The independent network-service example and native desktop child consume the same port; consult docs/native-network.md and keep secret-agent/hardware gaps explicit.
- BluetoothPort's BlueZ adapter owns one observing connection and bounded command queue. Keep transient handles distinct from addresses and global discovery distinct from discovery acquired by that connection. Its local executor drives pending native calls while the owner routes Agent1 callbacks and user replies. Pair/Connect admission, answer delivery and actual completion are distinct. Connect owns a separate transient BluetoothConnectionId; cancellation must validate that exact live attempt and use the urgent native lane. Join Connect/cancellation replies in either order without turning denied cancellation into Cancelled or erasing a successful Connect. Validate current attempt/request IDs, unique BlueZ sender and prompt kinds; PIN/passkey answers consume zeroizing owned storage. Observation registers no agent; explicit incoming/default-agent authority differs from outgoing application registration and radio discoverability. Close uncertain connections so stream clones cannot retain discovery/agent ownership. Release invalidates authority immediately, but connection retirement waits for its native response-dispatch notification. Preserve retirement intent across an interrupted operation completion. Native pairing protocol tests and desktop injection exist; consult the Bluetooth child and its private zeroizing form. Owned virtual-controller native radio, pairing/bonding, decline/Escape termination, unpaired Disconnect and compatibility routing pass; pending-profile/incoming/PIN-entry and physical-controller/profile acceptance remain open (reports/measurements/lucent-bluetooth-rejection.json and lucent-bluetooth-connection.json). Consult docs/native-bluetooth.md and the independent consumer. Never automatically accept, trust or replay a pairing attempt, or treat Connect acknowledgement as all profiles connected.
- Prepare images with `ImageData::from_rgba` or explicit `from_alpha` on an asset worker. Validated immutable storage includes mip levels; `format()` identifies premultiplied RGBA8 or single-channel coverage, and `pixels()`/`ImageLevel.pixels` use that format. Alpha8 reconstructs premultiplied white before element tint; never infer a mask from arbitrary colored artwork. Views and paint never generate image mips. Asset workers can use ImageData::downsample to copy only smaller prepared mip levels without retaining a full-size allocation or premultiplying pixels again. Each Canvas retains its current scene's GPU resources. Cache eviction removes unused least-recently-used entries; active payload can exceed the reuse budget and is reported separately from driver/framebuffer memory.
- `Event::Resize` includes logical dimensions and integer buffer scale, including configured-surface scale changes. Display asset preparation uses checked physical dimensions. `ImageData::downsample_for_cover` retains sufficient existing mips for both physical edges, keeping the base if the source is too small; `aspect_size()` preserves natural cover/contain geometry through odd mip sizes. This controls retained pixels, not decoder peaks, framebuffer memory or per-monitor policy.
- Use opt-in `LUCENT_PROFILE_FRAMES=1` to inspect the latest 120 successful submissions per surface. CPU stages include driver waits; text raster/upload breakdowns are nested within preparation. Never label these as GPU execution or scanout time. Keep instrumentation in runtime/renderer, with no domain/client coupling or extra redraws. Payload counters and Linux RSS/PSS snapshots have different scopes and do not yield total GPU memory.
- The shared Gpu asks wgpu for MemoryHints::MemoryUsage. Treat it as a backend allocation preference, not a byte limit or a guaranteed improvement. Preserve density, validate resources and record actual same-workload RSS/pacing when changing allocation policy. Queue submissions already perform wgpu maintenance; do not add an idle polling loop on speculation.
- `Clip` is shared presentation geometry for paint, pointer hits and Wayland input regions. Preserve all rounded ancestors. Cover images crop source UVs while retaining destination bounds/radius. Native regions quantize by logical pixel centers; edge antialiasing does not imply input coverage. Keep clipping behavior in the framework and verify GPU pixels at 1×/2× when changing it.
- Primitive/rounded-clip antialiasing uses explicit fine derivatives. WGSL's unsuffixed derivatives can choose coarse evaluation and change corner coverage across drivers. Preserve mirrored coverage at 1×/2× and run focused GPU checks on available software/hardware drivers; do not relax visual tolerances to hide a driver-dependent shader defect.
- Validate output extents through the renderer's shared checked conversion before native configuration or offscreen allocation. Check the requested device's limits, not just adapter capabilities; snapshots include aligned readback and host slice limits. Keep zero-size native retry behavior. These are validity checks, not memory budgets or evidence of OOM/device-loss recovery. Scene textures, text and geometry need their own validation boundaries.
- Evaluate shader derivatives and implicit texture sampling before rectangular discard. Use physical sample centers converted to logical coordinates for clip tests, with right/bottom exclusion matching Rect::contains. Preserve opaque odd-sized image edges and exact fractional clip-boundary regressions at 1×/2× on available software/hardware drivers.
- Keep the IPC server guard scoped inside the instance lock. Shutdown cancels producer delivery before joining, wakes through the poller rather than the socket pathname, and removes only the recorded file identity. Bound connected I/O with absolute deadlines; per-read timeouts alone allow slow peers to extend shutdown. Preserve ready quit acknowledgements and keep the idle listener asleep.
- Runtime teardown drops GPU surfaces before their protocol roles and flushes queued destruction while the connection remains live, including error returns. Verify native surfaces disappear when a caller outlives one runtime invocation, as the permission agent does. Cleanup never authorizes session unlock; retain the explicit authenticated gate.
- Effects::recreate_surface explicitly renews an ordinary non-reserving native lifetime at one unchanged SurfaceAddress. Reject positive committed, pending or replacement exclusive zones before native mutation; layer-shell has no atomic cross-surface reservation transfer. Keep one input-disabled last-good presentation until the replacement successfully submits; repeated requests cannot retain an unpainted pending surface instead. Revalidate exact native object identity after synchronous callbacks and between native message deliveries; old events cannot target the replacement. Preserve logical frame/timing/profile history separately from native submission count and release both lifetimes on hide/remove/failure/teardown. Secure session-lock runtimes must reject recreation before any effects mutate state; never create duplicate lock roles or an insecure fallback. Coordinate-space policy stays in clients, with no compositor-global coordinate inference in the engine.
- The runtime owns application state on one UI thread. `view` describes a tree; `update` changes state and requests effects. Child routing uses `Element::map` and `Effects::delegate`. Redraw requests coalesce per surface; they do not paint immediately.
- SurfaceSpec margins are logical protocol requests. TopLeft requires explicit width/height; omitted dimensions require opposite anchors. Validate IDs and anchor dimensions before native mutations. PointerInput is independent of keyboard mode and tree paint; None must submit an empty native region. A redraw group matches generic effects without client identities in the engine. Element::input_only retains layout, hits, focus and capture while suppressing all descendant paint; zero opacity does not preserve input.
- `Event::FrameSubmitted` reports successful submission after scene bookkeeping, with the view's time and logical buffer extent. It is not GPU completion or scanout; frame callbacks separately pace dirty work. Return no message when no client state change is needed. `Shadow::blur_outset` supplies the renderer's finite support; crop/grid policy stays in clients.
- `Element::scroll` is controlled vertical scrolling: validate a logical-pixel `ScrollSpec`, give the viewport bounded height and its single content tree intrinsic/fixed height, store returned offsets and redraw. Stable IDs retain focus/capture. Wheel routing follows the topmost hit's actual scroll ancestry; unrelated overlays must not scroll underlying siblings. Nested keyboard reveal emits a batch applied before drawing. Layout clamps presentation without silently mutating client state; data-set replacement/reset policy belongs in the client. Share immutable hit/clip ancestry, preserve rounded paint/input/focus agreement and cancel thumb capture when geometry changes. Use the independent `scroll-list` example and focused 1x/2x GPU/native tests. This control does not virtualize item layout; touch/kinetic/horizontal scrolling remain separate features.
- Effects execute on bounded, named ordered queues (at most nine workers, 64 waiting tasks per queue). Keep dependent writes on the same queue; independent queues can complete in any order. `Effects::delegate` preserves queue, cancellation and task-local failure routing. `task_on_with_failure` maps rejection/panic into the owning task's message; its mapper must remain nonblocking because rejected admission runs it on the UI thread. Cancelled work skips its mapper; a mapper panic or absent mapper falls back to `Application::runtime_failure`. Running work cancels cooperatively. Subscription identity retains captured values until removed/recreated. Runtime message delivery holds at most 64 waiting values; producers wait when full and cancellation releases the wait. Never send from the UI thread or while holding a lock needed by it. Queued events from cancelled subscriptions are discarded before update. At most 64 live subscription workers exist, including cancelled streams still stopping. Message payload sizes remain client-owned; this is not a byte budget or general async executor.
